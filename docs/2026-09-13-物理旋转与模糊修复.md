# 2.0.25 物理旋转与背景模糊修复

## 依据

- [AOSP RotationUtils](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/core/java/android/util/RotationUtils.java)：物理坐标到 ROTATION_90 逻辑坐标的变换是 `(x,y) -> (y,W-x)`，内容应旋转 -90°。原实现将 90° 与 270° 写反，且只映射中心，导致左右错位和长轴方向错误。
- [AOSP 窗口模糊](https://source.android.com/docs/core/display/window-blurs)：局部模糊使用 Window.setBackgroundBlurRadius，背景 drawable 规定区域，窗口需要透明和浮动配置；系统能力可能动态关闭。RenderEffect 不会采样其他应用窗口。本次保持局部跨窗口模糊，不使用全屏 blur-behind。

## 实现

几何先在机身竖屏坐标计算，再变换完整窗口矩形；TextureView 和精确触控 Path 使用同一旋转矩阵。手势的原始屏幕位移、速度反向转换为机身坐标。机身顶端的渐变方向同步转换。通过 DisplayManager 监听处理竖屏倒置等不会改变宽高的旋转。

模糊窗口采用专用透明浮动主题，显式开启硬件加速。创建顺序为背景压暗、模糊窗口、玻璃球、触控代理；启停模糊不重建窗口，不改变前后层级。服务结束销毁预留窗口。椭圆使用内接圆模糊，保证效果不超出玻璃轮廓。异常记录到 GlassOrbBlur 日志。

## 自动验收

- JVM：覆盖四向坐标、完整图形尺寸、物理边界、向下展开间隔、手势向量、模糊资格、内接圆和重复启停生命周期。
- Android 模拟器：PhysicalRotationAndBlurTest 使用真实 GLES 和系统合成器截图，验证四向位置及长轴、点击展开及向机身顶端滑动收起；比较棋盘格背景开关模糊前后的像素方差，检查区域外保持清晰和关闭恢复。
- 目标手机当前 ADB 离线，模拟器结果不能代替该手机 ROM 的最终视觉验收。系统不支持或关闭跨窗口模糊时，应用不能强制开启该能力。

执行命令：

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest --no-daemon --project-cache-dir /tmp/glass-orb-gradle-project-cache
adb -s emulator-5554 shell am instrument -w -r -e class com.cxcboss.glassorb.overlay.PhysicalRotationAndBlurTest com.cxcboss.glassorb.test/androidx.test.runner.AndroidJUnitRunner
```

安装包为 2.0.25 / versionCode 35，包名和权限集合不变。完整验收结果见 dist/测试说明.md。
