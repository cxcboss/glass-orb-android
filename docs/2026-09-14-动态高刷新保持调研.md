# 动态高刷新保持调研

日期：2026-09-14

## 结论

玻璃球展开、思考、跟手形变与自动收起属于持续动画，目标是让它们持续投票 120Hz；完全收起为静态灵动岛时，停止渲染提交并撤销高刷投票，让系统自然进入最低刷新率。

公开 Android API 不能无条件覆盖厂商的全局省电、温控、低电量或高优先级窗口策略。因此“始终满帧”的可实现定义是：设备和系统策略允许 120Hz 时，持续声明 120Hz，且不因触摸超时或动画稳定而自行撤销；系统拒绝时记录实际显示模式并安全回退。

## 已定位的当前缺口

当前 `GlRenderLoop` 对 `TextureView` 的 Surface 使用：

```kotlin
surface.setFrameRate(120f, Surface.FRAME_RATE_COMPATIBILITY_DEFAULT)
```

`DEFAULT` 允许系统选择低于应用请求的刷新率。当前 Overlay 的窗口模式和 `preferredRefreshRate` 也都只是系统偏好，不能阻止 HyperOS 在触控 Boost 到期后回到 60Hz。

## 小米真机采样（23127PN0CC / Android 16 / HyperOS 3.0）

2026-09-14 的实际采样推翻了“面板在等待后降到 60Hz”的假设：

- `dumpsys display` 在点击后 0、2、7、13 秒均显示 SurfaceFlinger mode 3 / `120.00001Hz`；
- 玻璃球宿主窗口与 SurfaceFlinger 图层均持续显示 `preferredRefreshRate=120.0` 和 `requestedFrameRate=120.00Hz`；
- 小米 SurfaceFlinger 的 touch timer 为 3000ms，但触控计时器到期后面板仍维持 120Hz；
- 临时低频帧率探针显示：主线程 Choreographer 约 `108–113` 次/秒，实际 `textureView.submit` 仅 `58–64` 次/秒，`eglSwapBuffers` 同样仅 `58–63` 次/秒。

根因在应用的 producer cadence gate，而不是显示模式：

```kotlin
frameTimeNanos - lastRenderSubmitNanos >= 1_000_000_000L / 120
```

右侧阈值固定为 `8,333,333ns`，但小米的实际应用 vsync 间隔约 `8.31ms`。单次回调常常略短于阈值，导致本应提交的帧被跳过；下一次间隔约 `16.62ms` 才通过，于是形成稳定的隔帧提交（约 60fps）。GL 队列只是忠实地执行这些被减半的提交，并非 GPU 性能不足。

修复应移除展开态的这个时间门限：只要收到 Choreographer 回调就提交最新快照。完全收起时现有状态机已经停止回调，仍会自然进入极致省电。帧率请求保留为系统层面的 120Hz 投票，但不再用于软件侧限频。

## 官方处理路径

1. **对真正绘制的 TextureView 持续投票。** Android 文档说明：明确为 `TextureView` 或 `SurfaceView` 设置的帧率会被应用。展开态应对该 View/Surface 声明 120Hz；完全收起后清除该声明。
2. **Android 15 / API 35 及以上关闭该窗口的 ARR 省电平衡。** 对渲染宿主及相关覆盖窗口设定 `frameRatePowerSavingsBalanced = false`，避免系统因为动画视觉上稳定而主动降档。
3. **Android 16 / API 36 及以上使用 UI 专用的 `FRAME_RATE_COMPATIBILITY_AT_LEAST`。** 官方定义它为 UI、动画、滚动和 fling 所用的“至少该帧率”请求。旧系统继续使用兼容的 `DEFAULT` 路径，不能传入新常量。
4. **展开态保持请求，收起态极致省电。** 波形、思考、拖拽、展开/收起过程中保持高刷；只在 `Collapsed` 且按压回弹结束时停止 Choreographer / GL 提交、清除高刷声明。
5. **用真机轨迹验证而非主观估帧。** 通过 `DisplayManager` 的模式回调、SurfaceFlinger 层列表 / 时间戳和 Perfetto 的 SurfaceFlinger + gfx 轨迹，分别记录点击瞬间、触控超时后、自动收起三个阶段的显示模式与实际提交间隔。

## 真机采集目标

需要已连接的小米设备。在不修改系统设置的前提下采集：

- 支持的显示模式、当前 modeId 和刷新率；
- 玻璃球 `TextureView` / Overlay 图层在触控后与超时后的 SurfaceFlinger 帧率；
- 是否因低电量、温控、游戏加速、全局高刷设定或其它前台窗口导致请求被拒绝；
- 自动收起期间的 Choreographer 回调间隔、GL swap 间隔和显示实际刷新率是否一致。
